# 形态兜底转换器（`脚本/convert.py`）

白名单优先、多形态兜底的单页 HTML → Markdown 转换器。零第三方依赖，只用 Python 标准库（3.11+ 验证，3.13 亦可）。

它和其它两个分支的定位差别：`html_to_md.py` 靠 DOM 结构与 BeautifulSoup 走通用富文本；`convert.py` 走**确定性判据 + 白名单 class**，适合「站点版式固定、噪声极多、必须逐字节可复现」的一次性处理。它不承诺通吃复杂排版——真要通吃，用 pandoc（见 `脚本/html2md_batch.ps1`）。

## 三条不变原则

1. **不脑补**：文件名与内容不符时只按实际内容转换，并在注记里如实写出不符，绝不按标题编造正文；
2. **白名单优先**：只收 class 命中的结构化区块，导航、二维码、备案号、`<script>`、`<style>`、`data-v-*`、SSR payload 天然丢弃；
3. **可复现**：默认不写盘，写盘先备份；同一源文件再跑一次产出等价。

## 用法

```powershell
cd 脚本

# 只读预检：编码、一致性告警、形态、残留，一字节不写
python convert.py 页面.mht --check

# dry-run：生成的 Markdown 打到 stdout，仍不写盘
python convert.py 页面.html

# 写盘：生成同名 .md，已存在先备份 .md.bak
python convert.py 页面.html --apply

# 归档用：成品前面加 YAML 头（title / source），这样 md_verify --strict 才通过
python convert.py 页面.html --apply --frontmatter
```

| 参数 | 行为 | 写盘 |
|---|---|---|
| （无） | dry-run，MD 打印到 stdout，stderr 提示 `[dry-run] 未写盘` | 否 |
| `--check` | 只读预检报告，不生成正文 | 否 |
| `--apply` | 写 `<同名>.md`，已存在先备份 `.md.bak` | 是 |
| `--apply --no-backup` | 写盘但不备份 | 是 |
| `--frontmatter` | 成品前加 `title` / `source` 的 YAML 头 | 跟随模式 |

`--check` 与 `--apply` 互斥；`--no-backup` 单独使用判用法错误（退出码 2）。退出码：运行期异常 `1`，用法错误 `2`。

## 四种形态

白名单的两张表任一非空 → 走白名单路径；皆空 → 按形态兜底。

| 形态 | 判据 | 输出 |
|---|---|---|
| 白名单结构化区块 | class 命中 `SECTION_CLASS` / `RECENT_ITEM_CLASS` / `REPLAY_ITEM_CLASS` | H1 + 注记 + 两张表（单元格内 `\|` 转义、`/` 补白） |
| 问答 | `h1#questionTitle` 或 section class 含 `best-answer` | `# 问题` + `## 最佳答案` + 正文 + `## 其他回答` + `### 作者` |
| 表单 | `div.question` ≥ 2 且 `div.question-title` ≥ 2 | `# 表单名` + `> 副标题` + 序号/字段/说明/已填值四列表 |
| 知乎搜索结果 | `<title>` 含「搜索结果」+「知乎」或 saved-from-url 含 `/search?`，且 `ContentItem-title` ≥ 2 | 标题 + 4 行诚实注记 + 结果列表（标题带原链接 + 缩进摘要）+ 相关搜索 |
| 通用文章 | 其余情况（保守兜底） | 标题 + 有序块流：段落 / `h2+` / 列表 / 围栏代码（微信图文按 `</li>` 还原换行、合并被翻译 `<font>` 切碎的段落、去公众号 id 与推广段） |

兜底不还原表格与图片，也不解出 MHTML 内嵌图。`.mht` / `.mhtml` 容器会先用标准库 `email` 解包出首个 `text/html` 部件再解析。

文章形态的三条硬规则（都是 review 时改出来的，见踩坑记录末尾）：

- **文档标题只取首个 H1**，不把 H1 与后续 H2 拼成一串；
- **H1 不进块流**，避免正文里重复一个 `## 标题`；
- **没有 `<pre>` 包裹的裸 `<code>` 也收成代码块**，否则文字会整块消失；段内行内 `<code>` 仍按普通文本处理。

## 流程与纯函数

| 步骤 | 函数 | 做什么 |
|---|---|---|
| 编码 | `detect_decode(raw)` | NUL 字节 → `not-text`；剥 UTF-8 BOM；`utf-8` → `gb18030` 严格解码；全失败 → `not-text` |
| 一致性预检 | `consistency_check(filename, html)` | 在**可见正文**（剥 script/style/标签后）数专题关键词；命中 0 → 告警但不阻断 |
| 白名单抽取 | `parse_sections(html)` | `HTMLParser` 子类按 class 白名单栈式收集字段，`DROP_TAGS` / `DROP_TEXT_HINTS` 丢噪声 |
| 形态判定 | `_shape_of(html)` | 问答 / 表单 / 知乎搜索 / 通用文章 |
| 兜底抽取 | `parse_generic(html)` | `_GenericParser` 或 `_ZhihuSearchParser` |
| 渲染 | `render_markdown` / `render_generic` | 按形态分派渲染 Markdown |
| 残留检测 | `residual_noise(md)` | 扫生成 md 里的 `<script` / `<div` / `data-v-` 残留（跳过 `>` 引用行） |
| 分派 | `_render_any(html, filename, check)` | 白名单优先，皆空才走兜底 |

## 边界

- 白名单 class 写死在 `convert.py` 顶部常量里：换站点要重探 DOM、改常量、补 fixture（先 RED 后 GREEN）；
- 问答页只抽问题与答案正文（赞数、时间、头像、「查看全文」按钮丢弃）；表单页只抽字段表格（页面自带的校验错误不保留）；
- 单站点适配 ≠ 通用转换器；`article` 兜底只保证「正文不丢、噪声不带」，不保证排版还原；
- 不下载远程图片，不解 MHTML 内嵌图片，不补知乎 `js-initialData` 全文。
